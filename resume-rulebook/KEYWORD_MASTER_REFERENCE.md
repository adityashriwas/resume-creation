# Keyword master reference

Read [methodology and source register](RESEARCH_METHODOLOGY.md) before using counts. These are **coded concept mentions in a small purposive sample**, not ATS weights, mandatory-skill rates or hiring probabilities. R/P/D distinctions remain in [postings.json](research/postings.json). Counts include requirements, preferences and duties, once per posting. Role abbreviations: SDE, SWE (Software Developer), FS, BE, FE, MOB.

Priority formula: Core ≥50% and ≥3 mentions; Important ≥2 otherwise; Optional =1. Zero has no observed priority. Every keyword is also **Conditional** on truthful candidate evidence and target relevance. **Avoid** any unsupported usage, keyword stuffing, wrong professional attribution or irrelevant stack. Interview and formatting advice are general professional guidance.

## Category coverage

1. Languages and fundamentals; 2. DSA/problem solving; 3. CS fundamentals; 4. Frameworks/UI technologies; 5. APIs/integration; 6. Databases/modeling/queries; 7. Design/architecture; 8. Testing/debugging/quality; 9. Version control/workflow; 10. Cloud/deployment/CI/CD; 11. Security/auth; 12. Performance/reliability; 13. Features/role responsibilities; 14. Communication/collaboration/learning; 15. Education/experience/portfolio.

Operating systems and DBMS are not synonyms for Linux and database mentions. OS has weak direct support in the retained sample; include coursework only if verified. Detailed data modeling, authentication versus authorization, security mechanisms and specific testing tools must be checked in the target JD and actual implementation. Do not infer frequencies for unannotated subterms.

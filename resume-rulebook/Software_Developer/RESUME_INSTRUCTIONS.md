# Software Developer / Software Engineer — resume instructions

Read [shared rules](../SHARED_RESUME_RULES.md), [candidate evidence](../CANDIDATE_EVIDENCE.md), and [keyword matrix](../KEYWORD_MASTER_REFERENCE.md) first. Research accessed 22 October 2026. Resume-writing, ordering and interview suggestions below are general professional guidance derived from the cited work scopes; they are not claims about every recruiter or interview.

Research cohort: [J05](https://www.bornwest.com/careers/entry-level-software-developer), [J06](https://newstreettech.com/careers/associate-software-engineer), [J07](https://www.heizen.work/careers/associate-software-engineer), [J08](https://advancesensing.com/pages/careers/careers/software-engineer.html), [J09](https://jobs.lever.co/Allata/a0eb9210-f90b-4a71-9107-765fb4848001), [J31](https://careers.americanexpress.com/en/sites/CX_1/job/26014930/?intlink=us-amex-career-en-us-navigation-jobs). See [methodology](../RESEARCH_METHODOLOGY.md) for small-sample and eligibility limits. Cross-role comparisons may cite other register IDs.

## 1. Role and routing

Target Junior Software Engineer, Associate Software Engineer, Software Developer and entry-level Software Engineer. This version balances feature implementation, debugging, maintainability and collaboration. Prefer SDE when the JD stresses general algorithmic engineering, Full Stack for cross-layer ownership, Backend for services/data, Frontend for browser UI, and Mobile for device applications. Title alone cannot decide.

## 2. Early-career expectations

J06/J07 emphasize reviewed contributions, tests and learning; J09 specifically accepts 6–12 months. Responsibilities can span a codebase without requiring senior ownership. J08 adds an industrial domain, showing that generic Software Engineer does not always mean web development.

## 3. Keyword priorities

Core practical emphasis: programming, maintainable features, debugging and teamwork (J05–J09). Important: Git, SQL, APIs, tests and code-review feedback. Optional: specific domain tools, cloud or AI tooling when requested. Conditional: OOP/DSA study and specific test/deployment contributions require accurate evidence labels. Avoid generic claims of mastering all stacks. For measured priority and coverage of all 15 categories, use the SWE column of the master matrix.

## 4. Required versus preferred

J05 requires fundamentals and basic SQL/Git while Rails/React experience is preferred; J06 requires working Python; J09 needs .NET/C# foundations. Current JavaScript experience cannot be relabeled Python or C#. J31 requires 1–2 professional years and is not an automatic match at six months.

## 5. Technical skills order

Relevant language → application frameworks → APIs and databases → version control/tools → verified test tools. Match the target ecosystem rather than presenting frontend/backend/mobile headings as three equally deep professional specialisms.

## 6. Resume sections and fixed layout

Preserve the current template, headings, section order, fonts, margins and all spacing. The user alone makes layout changes manually. Emphasize real Sofmen delivery, debugging and a distinct project contribution within the current sections. Keep exactly one page by editing and selecting content, not by changing formatting. Compile and verify page count and absence of overflow before delivery.

## 7. Project selection

Select one strong user workflow and one different engineering contribution. ExpressU offers mobile integration; TaleCrafter adds web/server work. SafetyBriefer is useful only with a specific attributable maintenance contribution rather than duplicating another mobile app's technology list.

## 8. Bullet structures

Use a natural length for the contribution: combine related implementation details and outcomes, split unrelated material, and avoid repetitive openings or endings. Examples are not length targets or mandatory sentence patterns.

Use action → feature or defect → collaboration/method; or workflow contribution → engineering context. The following are resume-reported Sofmen claims, rewritten without adding metrics or senior ownership.

```resume-example
Collaborated with senior engineers on feature delivery while maintaining source control workflows in Git and GitLab.
```

```resume-example
Resolved functional defects and refined application interfaces through stakeholder feedback during development.
```

## 9. Expected responsibilities and outcomes

Show implementation from requirements, defect resolution, applied feedback and maintainable changes. J06 supports learning through review and tests; J09 includes documentation and SQL work. State specific work you performed, not everything expected of the team.

## 10. Claims requiring extra evidence

Code-review leadership, formal Scrum participation, automated-test authorship, deployment ownership and cross-product impact need confirmation. Working under deadlines is not proof of managing a release or team.

## 11. ATS wording

Software development, feature implementation, bug fixes/defect resolution, debugging/troubleshooting, version control and code quality are useful variants. Use one natural phrase, not slash-separated synonyms in every bullet. SQL Server and PostgreSQL are separate technologies.

## 12. Summary guidance

Describe an early-career developer with real mobile frontend delivery and relevant project breadth. Name the target stack only where supported. Omit a generic objective such as seeking a challenging environment.

## 13. Professional experience

Keep the exact Junior Software Engineer title and mobile-team context. Explain design implementation, working with backend engineers and responding to feedback. Professional API integration does not demonstrate professional server implementation.

## 14. Interview signals

General professional guidance: prepare a bug reproduction, the change made, how it was checked, and how feedback altered the implementation. Explain a Git collaboration flow actually used; do not invent release ceremonies or review responsibilities.

## 15. Final resume checklist

Confirm the current formatting and section order are unchanged, and the rendered resume is exactly one page with no clipping or overflow. Confirm target-stack fit and tenure; lead with real employment; use bounded action verbs; connect features to user tasks; keep one or two distinct projects; check reading order, bullet clarity and visual balance; verify quoted achievements.

## 16. Repetition and weak-claim checklist

Avoid three versions of collaborated with the team. Separate implementation, debugging and workflow evidence. Replace vague worked on software only when a truthful specific contribution is available; do not manufacture a feature to make the wording stronger.

Read [shared rules](../SHARED_RESUME_RULES.md), [candidate evidence](../CANDIDATE_EVIDENCE.md), and [keyword matrix](../KEYWORD_MASTER_REFERENCE.md) first. Research accessed 22 October 2026. ## 1. Role and routing

Target Junior Full Stack Developer, Full Stack Engineer and Software Engineer roles explicitly spanning UI, server logic and persistence. Choose this version only when both sides are evidenced. SDE stresses broader reasoning, Software Developer balanced maintenance, Backend services/data, Frontend browser delivery, and Mobile device behavior. Mobile plus API consumption alone is not full-stack development.

## 2. Early-career expectations

J05/J09/J10/J11 show several stacks and guided cross-layer delivery. J13 combines React Native with Java backend work. Full-stack therefore does not mean MERN by definition. J35 has a junior title but broad infrastructure demands; assess fit separately.

## 3. Keyword priorities

Core practical emphasis: frontend-to-backend features, API boundaries, database use and maintainable implementation (J05/J09–J14). Important: language fundamentals, validation, Git, SQL and testing. Optional: cloud/containers, serverless or employer-specific AI tools. Conditional: authentication, data modeling and release work need actual contribution evidence. Avoid MERN when MongoDB is not used and end-to-end ownership when only one layer was authored. See the FS column for all 15 categories and measured prevalence.

## 4. Required versus preferred

J09 asks for .NET/C# and React or Angular; J10 uses Python/Node and Angular; J11 asks for React/Node/SQL and treats Next.js/NestJS as preferred exposure. J13 requires WatermelonDB; generic local storage is not equivalent. Match individual hard gates without inventing stack experience.

## 5. Technical skills order

JavaScript/TypeScript → React/Next.js → Node.js/Express.js → PostgreSQL/Drizzle → APIs/auth integrations → Git/tools. Change ordering for the target only when the underlying skill is real. Keep mobile libraries secondary unless the role includes mobile.

## 6. Resume sections and fixed layout

Preserve the current template, headings, section order, fonts, margins and all spacing. The user alone makes layout changes manually. Keep professional experience truthful and concise; prioritize attributable TaleCrafter UI/server/data workflows within the existing Projects section. Keep exactly one page by editing and selecting content, not by changing formatting. Compile and verify page count and absence of overflow before delivery.

## 7. Project selection

Lead with TaleCrafter, showing one user action through browser, API, authorization and persistence where personally attributable. Use ExpressU as complementary client integration evidence, not a second full-stack claim. Avoid presenting SafetyBriefer's external backend as your server work.

## 8. Bullet structures

Use a natural length for the contribution: combine related implementation details and outcomes, split unrelated material, and avoid repetitive openings or endings. Examples are not length targets or mandatory sentence patterns.

Use user workflow → frontend/server integration → saved or accessible result. Pair an application workflow with a distinct auth/payment boundary instead of listing every API provider. Examples are existing TaleCrafter resume claims; confirm personal contribution and current implementation before reuse.

```resume-example
Built an illustrated-story application with Gemini text generation, Pollinations images and Cloudinary media storage.
```

```resume-example
Integrated Neon Auth and Razorpay subscriptions with backend ownership checks and subscription access controls.
```

## 9. Expected responsibilities and outcomes

Demonstrate a complete feature path, contract handling and persisted state; explain loading/error behavior or access checks if authored. J09 supports UI/API/database coordination; J11 supports small scoped work under review. Deployment and monitoring remain separate evidence questions.

## 10. Claims requiring extra evidence

Backend ownership, schema design, transactional correctness, webhook idempotency, CI/CD and production reliability need attributable implementation. Repository analyses describe these topics but do not establish who built them. No invented payment volume, revenue or AI accuracy.

## 11. ATS wording

Full stack/full-stack, REST API development, API integration, relational database, frontend components and server-side logic are distinct terms. Use Express.js for the framework, not the ExpressU application. LLM integration means calling a model service, not training models.

## 12. Summary guidance

Connect professional React Native exposure with personal full-stack web work. Make the distinction explicit in a short sentence. Prefer a demonstrable application workflow over a generic claim to own the entire software lifecycle.

## 13. Professional experience

Keep Sofmen responsibilities frontend-focused and truthful. Use collaboration with backend engineers to show integration experience, not backend authorship. Let TaleCrafter establish server-side breadth independently of employment.

## 14. Interview signals

General professional guidance: trace a request from UI input to persisted result, explain where validation and authorization occur, and describe failure handling. Be able to identify inherited code and a concrete change you made at each claimed layer.

## 15. Final resume checklist

Confirm the current formatting and section order are unchanged, and the rendered resume is exactly one page with no clipping or overflow. At least one attributable UI/server/data workflow; accurate project context; actual database named; auth and payment scope qualified; no unverified cloud ownership; relevant professional experience retained; coherent bullets with natural lengths and readable layout.

## 16. Repetition and weak-claim checklist

Avoid repeating integrated APIs in every project. Distinguish story creation, persistence and access control only when each adds evidence. Do not use a stack line as a substitute for contribution, or repeat the same provider names in summary, skills and every bullet.
